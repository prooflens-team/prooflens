# PROOFLENS RAG & Evidence Verification

## 1. 모듈 개요

광고 분석 AI에서 추출한 효능 및 안전성 주장을 외부 근거자료와 비교하여 검증하는 RAG 기반 모듈입니다.

PostgreSQL과 pgvector를 활용하여 관련 근거자료를 검색하고, Gemini를 통해 광고 주장과 근거자료의 일치 여부를 판단합니다.

광고 주장뿐만 아니라 제품명, 성분, 광고대상, 시험대상, 시험인원, 시험기간 등의 맥락 정보를 함께 고려합니다.

외부 근거자료가 부족한 경우에도 광고에 표시된 시험 정보를 검토하고 소비자가 추가로 확인해야 할 사항을 제공합니다.

## 2. 기술 스택

- Python 3.11
- Gemini 3.1 Flash Lite
- Gemini Embedding 001
- PostgreSQL
- pgvector
- Supabase
- Pydantic
- NumPy
- pytest

## 3. 주요 기능

### 3.1 근거자료 관리 및 검색

- 근거자료 전처리 및 청킹
- 768차원 임베딩 생성
- PostgreSQL 기반 벡터 저장
- 코사인 유사도 기반 근거자료 검색
- 광고 맥락 기반 다중 검색
- 연구방법론 및 안전성 평가 관련 보조 검색
- 검색 결과 중복 제거

### 3.2 광고 주장 검증

- RAG 기반 광고 효능 및 안전성 검증
- 개별 광고 주장 단위의 독립적인 검증
- 제품명, 성분, 사용 조건 및 광고대상 고려
- 특정 제품의 시험 실시 여부와 일반적인 효능 검증 구분
- 연구 결과의 적용 범위 및 일반화 가능성 검토
- 근거자료 출처 제공

### 3.3 광고 자체 정보 검토

- 시험 시작일 및 종료일의 오류 탐지
- 광고대상과 시험대상 간 차이 검토
- 시험인원 및 시험기간 검토
- 건강한 시험대상자의 연구 결과 일반화 한계 검토
- 피부 자극도와 알레르기 및 이상반응 평가 구분
- 동일 제품에 표시된 복수 시험 정보 비교
- 외부 근거자료 부재 시 광고 자체 정보 검토 유지

### 3.4 소비자 안내 및 시스템 안정성

- 광고 맥락에 따른 구매 전 확인사항 생성
- Gemini 서버 오류 발생 시 재시도
- 근거자료 검색 및 AI 검증 시간 측정
- JSON 기반 백엔드 모듈 연동
- 표준 출력과 표준 오류 스트림 분리

## 4. 광고 주장 판정 기준

| 상태         | 의미          | 판정 기준                                                                                          |
| ------------ | ------------- | -------------------------------------------------------------------------------------------------- |
| SUPPORTED    | 근거 확인     | 현재 광고 주장을 직접적으로 뒷받침하는 근거가 존재하는 경우                                        |
| CONFLICT     | 근거와 불일치 | 제공된 근거자료가 광고 주장과 직접적으로 모순되는 경우                                             |
| INSUFFICIENT | 근거 부족     | 관련 근거는 존재하지만 광고에서 주장하는 효능, 안전성 또는 적용 범위를 충분히 입증하지 못하는 경우 |
| UNVERIFIABLE | 확인 불가     | 관련 근거가 없거나 특정 사실을 확인할 직접적인 자료가 부족한 경우                                  |

특정 제품의 시험 실시 여부, 시험 결과 수치 및 전문가 확인 여부를 검증할 때는 해당 사실을 직접 확인할 수 있는 자료가 필요합니다.

일반적인 학술논문이나 안전성 평가 지침만 존재하는 경우 특정 제품의 시험 실시 여부를 입증한 것으로 판단하지 않습니다.

근거 부족 또는 확인 불가 판정은 광고가 허위라는 의미가 아닙니다.

## 5. 실행 환경 구축

backend 디렉터리에서 Python 가상환경을 생성하고 필요한 라이브러리를 설치합니다.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements-rag.txt
```

PowerShell 실행 정책으로 인해 가상환경 활성화가 제한되는 경우 현재 프로세스에 한하여 실행 정책을 변경할 수 있습니다.

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
```

## 6. 환경변수 설정

`.env.rag.example`을 참고하여 backend 디렉터리의 `.env` 파일에 다음 환경변수를 설정합니다.

```env
GEMINI_API_KEY=
GEMINI_MODEL=gemini-3.1-flash-lite
GEMINI_EMBEDDING_MODEL=gemini-embedding-001
EMBEDDING_DIMENSION=768
DATABASE_URL=
```

API 키와 데이터베이스 접속 정보는 외부에 공개하지 않습니다.

`.env` 파일은 GitHub 저장소에 포함하지 않습니다.

## 7. 데이터베이스 구축

PostgreSQL에서 `data/schema.sql`을 실행하여 pgvector 확장 기능과 근거자료 저장 테이블을 생성합니다.

다음 명령어를 실행하여 근거자료를 벡터로 변환하고 저장합니다.

```powershell
python -u rag/ingest.py
python rag/database.py
```

공용 데이터베이스에 최신 근거자료가 이미 저장되어 있다면 ingest 작업을 생략할 수 있습니다.

현재 데이터베이스에는 총 60개의 근거자료 레코드가 저장되어 있습니다.

### 9.3 입출력 방식

`run_rag.py`는 광고 정보와 주장 목록을 표준 입력으로 전달받아 검증 결과를 JSON 형식으로 표준 출력에 반환합니다.

진행 상황, 검색 시간, Gemini 응답 시간 및 재시도 정보는 표준 오류 스트림으로 출력합니다.

정상 실행 시 다음 구조를 반환합니다.

```json
{
  "success": true,
  "result": {
    "ad": {},
    "claims": [],
    "checkBeforeBuy": [],
    "disclaimer": ""
  }
}
```

오류 발생 시 다음 구조를 반환합니다.

```json
{
  "success": false,
  "error": "오류 메시지"
}
```

### 9.4 광고 맥락 확장 필드

기존 광고 정보 및 주장 구조를 유지하면서 다음 선택적 필드를 활용할 수 있습니다.

#### ad 필드

| 필드           | 설명                         |
| -------------- | ---------------------------- |
| brandName      | 브랜드명                     |
| productName    | 제품명                       |
| category       | 제품 유형                    |
| targetAudience | 광고대상                     |
| ingredients    | 주요 성분 목록               |
| conditions     | 광고 전체에 표시된 조건      |
| testConditions | 광고에 표시된 시험 정보 목록 |

#### testConditions 내부 필드

| 필드         | 설명                                  |
| ------------ | ------------------------------------- |
| id           | 시험 정보 식별자                      |
| sourceId     | 시험 정보가 추출된 이미지 등의 식별자 |
| testType     | 시험 유형                             |
| institution  | 시험기관                              |
| participants | 시험대상                              |
| sampleSize   | 시험인원                              |
| startDate    | 시험 시작일                           |
| endDate      | 시험 종료일                           |
| duration     | 시험기간                              |
| result       | 광고에 표시된 시험 결과               |

날짜는 가능한 경우 YYYY-MM-DD 형식으로 전달합니다.

확인되지 않은 시험 정보는 임의로 추정하지 않습니다.

#### claims 내부 확장 필드

| 필드       | 설명                                |
| ---------- | ----------------------------------- |
| claimType  | 광고 주장의 분야                    |
| sourceIds  | 주장과 연결된 광고 자료 식별자 목록 |
| testIds    | 주장과 연결된 시험 정보 식별자 목록 |
| conditions | 현재 주장에 직접 연결된 조건 목록   |

개별 주장에 연결된 시험 정보만 해당 주장 검증에 활용하여 다른 시험 조건이 혼합되는 것을 방지합니다.

확장 필드가 없는 기존 입력 데이터도 처리할 수 있습니다.

해당 확장 규격은 Backend C의 모의 입력 테스트를 기준으로 작성되었으며, Backend B 및 Express 서버와의 최종 연동 규격은 별도의 협의와 검증이 필요합니다.

## 10. 근거자료 및 검색 구조

### 10.1 검색 설정

| 항목                   | 설정값        |
| ---------------------- | ------------- |
| 근거자료 수            | 60개          |
| 데이터베이스 레코드 수 | 60개          |
| 임베딩 차원            | 768           |
| 검색 방식              | 코사인 유사도 |
| 기본 검색 Top-K        | 3             |
| 광고 맥락 검색 Top-K   | 3             |
| 보조 검색 Top-K        | 2             |
| 최소 유사도            | 0.65          |
| Temperature            | 0.1           |

Top-K는 개별 검색에 적용되는 설정값입니다.

광고 맥락 검색 및 보조 검색 결과를 병합하므로 최종 검색 자료의 수는 3개를 초과할 수 있습니다.

### 10.2 근거자료 구성

근거자료는 다음 분야를 포함합니다.

- 화장품 성분 및 효능
- 피부 노화 및 주름 개선
- 피부 보습 및 피부 장벽
- 여드름 개선
- 탈모 및 모발 성장
- 미백 및 색소침착
- LED 및 가정용 미용 기기
- 영유아 피부 특성
- 영유아용 화장품 안전성
- 피부 저자극 및 알레르기 평가
- 시험 결과의 통계적 해석
- 연구 결과의 일반화 및 적용 범위
- 국내외 표시·광고 관련 법령과 가이드라인

### 10.3 광고 맥락 기반 검색

기존에는 광고 주장 문장을 중심으로 근거자료를 검색하였습니다.

확장된 검색 방식에서는 다음 세 가지 검색을 활용합니다.

1. 광고 주장 원문 기반 검색
2. 제품명, 성분, 광고대상 및 시험 조건을 포함한 맥락 기반 검색
3. 시험대상, 시험기간, 시험인원 및 안전성 평가에 관한 보조 검색

검색 결과는 근거자료 ID를 기준으로 중복을 제거하여 병합합니다.

기본 주장 검색 결과를 우선 유지하며, 추가적인 맥락 검색 결과와 보조 검색 결과를 결합합니다.

### 10.4 광고 자체 정보 검토

`rag/ad_context.py`는 다음 기능을 담당합니다.

- 광고 정보 정규화
- 개별 주장과 시험 정보 연결
- 광고 맥락 기반 검색 문장 생성
- 연구방법론 관련 보조 검색 문장 생성
- 시험기간 오류 탐지
- 광고대상과 시험대상 차이 검토
- 시험인원 및 시험기간의 적용 범위 검토
- 복수 시험 정보 비교
- 소비자 확인사항 생성

광고 자체 정보 검토 결과는 독립적으로 검증된 외부 근거자료와 구분하여 처리합니다.

외부 근거자료가 검색되지 않는 경우에도 광고에 표시된 시험 정보를 검토할 수 있습니다.

## 11. 기능 및 자동화 테스트

### 11.1 자동화 테스트

```powershell
python -m pytest tests/ -v
```

| 테스트 파일        | 테스트 수 | 성공 | 실패 |

신규 광고 맥락 분석 테스트는 시험 정보 분리, 검색 문장 생성, 날짜 오류 탐지, 시험대상 비교, 검색 결과 중복 제거, 외부 근거 부재 시 광고 자체 검토 및 구매 전 확인사항 생성 등을 검증합니다.

자동화 테스트 통과율은 구현된 기능의 테스트 통과 여부를 의미하며 AI 판정의 일반적인 정확도를 의미하지 않습니다.

## 14. 한계 및 향후 개선 방향

### 14.1 한계

- 제한된 수의 근거자료를 사용하므로 모든 광고 주장을 검증할 수 없습니다.
- 근거자료 전체에 대한 원문 대조 검토가 필요합니다.
- 검색 유사도는 광고 주장의 진실성을 나타내는 확률이 아닙니다.
- 비교 실험은 소규모 표본을 사용하였으며 일반적인 모델 정확도를 보장하지 않습니다.
- 비교 대상 간 프롬프트와 재시도 정책에 차이가 있습니다.
- 출처 제시율은 출처의 존재 여부를 측정한 것으로 출처의 정확성을 보장하지 않습니다.
- 생성형 AI가 실제 판단에 활용하지 않은 자료를 출처에 포함할 가능성이 있습니다.
- 일부 생성 결과에서 제공된 근거의 범위를 넘어서는 단정적인 표현이 나타날 수 있습니다.
- 광고 자체 정보 검토는 광고에 표시된 정보의 정확한 추출을 전제로 합니다.
- 날짜 불일치 탐지는 표기 오류 가능성을 확인하는 기능이며 실제 시험의 진위 여부를 확정하지 않습니다.
- 시험 정보가 없는 광고의 맞춤형 구매 전 확인사항은 추가적인 개선이 필요합니다.
- 외부 API의 응답 지연 및 사용량 제한에 영향을 받을 수 있습니다.
- 생성형 AI의 특성상 동일한 입력에도 판정이나 설명이 달라질 수 있습니다.
- 영유아 광고 테스트는 Backend B의 실제 출력이 아닌 모의 JSON을 사용하였습니다.
- 광고 분석 AI 및 Express 서버와의 실제 통합 검증이 필요합니다.
- 전체 서비스의 60초 이내 응답을 보장하지 않습니다.

### 14.2 향후 개선 방향

- 근거자료의 지속적인 확충 및 원문 검증
- 신규 근거자료 기반의 독립적인 평가 데이터 구축
- 광고 맥락 기반 검색의 관련성 평가
- 벡터 검색 및 근거자료 재순위화 성능 개선
- 생성 결과와 인용 근거 간 일치 여부 검증 강화
- 특정 제품의 시험성적서 및 인증자료 검색 기능 확장
- 시험 정보가 없는 광고의 맞춤형 소비자 안내 개선
- 검증 목적 분류 및 판정 기준의 코드 수준 검증
- 광고 주장 병렬 처리를 통한 응답 시간 개선
- 반복 실험을 통한 판정 일관성 및 응답 시간 평가
- Backend A, B, C 통합 테스트 및 전체 서비스 응답 시간 측정

본 모듈은 소비자의 광고 판단을 지원하기 위한 것으로, 제품의 효능이나 안전성 또는 광고의 위법성을 확정하지 않습니다.
